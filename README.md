# 전문가와 AI가 함께 영한 번역하기

아직 '완벽한 자동번역'의 시대는 오지 않았으므로 여전히 전문번역가가 필요합니다. 하지만 번역가라도 **특정 분야의 용어와 기술, 전문 지식에 대한 이해도에 따라 번역의 품질이 좌우**될 수 있습니다. 일반적인 분야가 아니라면 번역 후에도 많은 수정을 거쳐야 합니다. 아예 특정 분야 전문가 또는 종사자가 직접 번역을 하는 것이 이상적일 수 있지만, 본업 외에 직업 번역가의 역할을 더한다는 것은 쉬운 일이 아닙니다. 이 프레임워크는 **연구자, 특수분야 전문가 등이 직접 번역**을 시도할 때 도움을 줄 수 있습니다.

## 프레임워크 개요

### 사용환경

* `구독형 AI` 환경에서 사용합니다.(API 방식은 고려하지 않았음)

> [!CAUTION]
> 이 프레임워크는 claude code 환경에서 구성됐으므로 다른 AI 환경에서 사용하려면 먼저 claude.md를 해당 AI에 맞게 수정하도록 AI에게 요청하세요.

> [!CAUTION]
> 번역과 감수는 서로 다른 AI에게 맡기는 것을 권장합니다.

* 원문은 '텍스트 정보에 결함이 없는' PDF를 대상으로 합니다.

> [!WARNING]
> 대체로 문서파일에서 PDF로 변환된 경우입니다. OCR 처리를 거친 PDF는 보통 오류가 많습니다.

> [!CAUTION]
> PDF는 우선 구조분석을 거쳐 마크다운 형식의 청크(chunk)로 분할되고 이로부터 번역 파이프라인이 가동됩니다. 현재는 원본이 PDF인 경우에 대해서만 테스트됐습니다.

* 전문가와 AI의 소통은 세션 프롬프트와 대시보드 양쪽에서 자유롭게 이뤄집니다.

### 역할

| **전문가(사용자)**      |  **AI**  |
| --------- | --------- |
| * 원문의 종류, 타겟 독자군, 번역의 톤과 세부 지침 지정<br />* 용어 및 번역 결과 컨펌<br />* 번역 순서, 방식 지시 | * 원문 파싱(markdown) 및 용어집 관리<br />* 번역 프로젝트 운영 관리<br />* 번역 및 감수 |

### 파일럿 프로젝트

* 이 저장소는 시범적으로 [*The Film Preservation Guide*(NFPF, 2004)](https://www.filmpreservation.org/preservation-basics/the-film-preservation-guide-download)로부터 일부 진행한 번역 관련 파일들이 포함되어 있습니다. 새 프로젝트를 시작하려면 아래 섹션을 참고하시기 바랍니다.

&nbsp;
## 새 번역 프로젝트 시작하기

### 1. 시작 묶음 받기

* [Releases](../../releases) 에서 `starter-*.zip` 을 받아 압축을 풉니다.
* 프로젝트 폴더를 생성하고 그 아래에 저장합니다.

### 2. 번역할 PDF 준비

* `intermediate/` 폴더 안에 번역할 PDF를 넣습니다.

### 3. AI 세션 시작

* 프로젝트 폴더를 연계한 세션을 열고 AI에게 다음과 같이 요청합니다.

    ```bash
    이 폴더에서 번역 프로젝트를 시작할 거야.
     @CLAUDE.md와 @ai_book_translation_pipeline.md를 읽고, PDF 원문의 구조 분석부터 시작해.
    ```
* 이후 AI가 절차대로 알아서 진행하고 확인을 요청할 것입니다. 만일 스스로 진행하지 않으면 요청하면 됩니다.
    * 단계별로 생성되는 다수의 청크 및 설정파일을 버전관리하기 위해서는 **버전관리 툴인 [git](https://git-scm.com/install/windows) 설치를 권장**합니다. AI에게 git을 설치해 달라고 요청하세요.

> [!CAUTION]
> AI는 결정론적 존재가 아니므로 실수를 할 수 있고, 이때 git으로 관리되고 있어야 복구할 수 있습니다.

### 4. 대시보드 실행

* 맥(OSX) 환경에서는 `대시보드 실행.command`를, 윈도우즈 환경에서는 `대시보드 실행.bat`를 더블클릭하여 대시보드를 실행하면 웹 브라우저에 로컬서버 형태로 열립니다.
* 대시보드를 구동하기 위해서는 파이썬 등이 설치되어 있어야 합니다. 대시보드 실행 전에 AI에게 환경을 확인하고 준비해 달라고 요청하세요.
* 대시보드를 재실행해야 하는 상황이 있을 수 있습니다. 이때는 대시보드 화면 상단의 `서버 재실행` 버튼을 누르거나, 서버 구동시 열린 터미널 창을 종료(또는 ctrl-C)하고 위 구동파일을 다시 더블클릭하면 됩니다.

### 이전에 번역했던 분야를 진행한다면

* `reference/` 폴더에 이전 프로젝트에서 생성된 용어집을 넣고 다음과 같아 지시합니다.
    ```bash
    레퍼런스 용어집을 넣어놨어. 현재 번역하는 문서에 등장하는 용어가 있다면 가져와줘.
    ```
* 용어집을 축적, 관리하는 것은 한 조직의 번역 일관성을 보장하고 번역 품질을 점차 개선하는 데에 가장 중요한 영향을 줍니다. 분야별, 유형별로 용어집을 관리하고 필요하다면 AI에게 정리/통합/엑셀변환 등을 요청해 보세요.

## 번역 프로세스

> `원문 정규화` → `AI 번역` → `AI 1차 감수` → `AI 2차 감수` → `전문가(사용자) 감수` → `AI 보완` → `완료`

* `원문 정규화`는 원본 PDF의 구조를 파악하고 구조에 적합한 파서(parser)를 적용하여 분할된 번역 소스(chunk/markdown)를 생성하는 단계입니다. 이 청크파일로부터 모든 단계마다 새 파일이 생성, 관리됩니다.

> [!WARNING]
> 이 단계에서 제대로 정리가 되지 않으면 이후 번역이 정상적으로 진행되지 않을 수 있습니다.  

> [!CAUTION]
> 원문 파일을 열어 `원문대조...` 마커가 있는 부분에 대해 AI에게 상황을 설명하면 오류 개선에 큰 도움이 됩니다. AI는 1차적으로 정규식 파싱을 실시하고 오류가 검출된 부분에 대해 이런 마커를 삽입하여 시각적 확인(visual check)을 2차로 실시합니다. 사용자의 조언을 통해 2차 작업을 생략할 수도 있습니다.

> [!CAUTION]
> 번역이 완료되면 최종 마크다운 청크 파일을 그대로 활용할 수 있습니다. 필요하다면 AI에게 이 파일들을 묶어서 다른 포맷의 파일로 변환해 달라고 요청해보세요.

* `1차 감수`는 원문과 번역문을 대조하며 누락, 오역, 숫자나 고유명사 등의 표기를 주로 확인하며, `2차 감수`는 번역의 톤과 용어집 준수 여부 위주로 점검합니다. 그러나 결국 전체적인 번역의 품질은 `AI 번역` 단계에서 사실상 결정되며, 전문가가 이에 대해 얼마나 세심하게 피드백을 주고 컨펌하는가에 최종 품질이 좌우됩니다. 특히 `용어집`은 번역 수준에 결정적인 역할을 하며, 복잡한 맥락마다 전문가의 판단이 내려져야 하는 부분입니다. 
* 이 프레임워크는 완전자동 번역이 아니라 전문가가 번역을 하는 데에 있어서 도움을 주는 툴로서 제공되는 것입니다. 용어의 확정, 번역의 컨펌은 여전히 전문가가 최종 판단을 해야 하며, 그 과정을 편하게 돕는 것이 대시보드의 역할입니다.

## 생성/관리되는 주요 파일 개요

| 파일·폴더                  | 내용                                |
| ---------------------- | --------------------------------- |
| `guide/tone-and-decision.md` | 톤 지침 + 한국어 표기 규칙 + **진행과정에서의 결정 기록**(로그) |
| `glossary/glossary.yaml`     | 용어집 / 원어·번역어 표기 및 맥락 정보 규칙                   | 
| `book-knowledge.md`          | 원문의 내용에 대해 AI가 이해한 내용을 기록(3~4챕터마다 검토)      | 
| `structure-map.yaml`   | 원서 구조, 청크 분할 내역, 구간별 파서(parser) 적용 현황, 조판 수치 등    |
| `source/*.md`          | **정규화된 원문**    |
| `chapters/*.md`        | **번역본**       |
| `stages/<청크>/*.md`     | 단계별 스냅샷. 이로부터 `대조` 뷰어 페이지를 구성함.   |
| `reviews/*.json`       | 감수 결과, 문단 승인·반려, 시각 확인 기록, 사용자 지시사항 기록 |
| `layout-manifest.yaml` | 원본에 무엇이 어디 있었는지. 파싱 누락 검증의 기준이 됨. |
| `status.md`            | 진행 상태             |

## 이후 개선 계획

* 향후 개선 사항 및 일정은 정해지지 않았습니다. 다만, 아래 사항이 반영될 수도 있습니다.
  * 각 단계의 markdown 파일 개별/통합 내보내기
  * 용어집 내보내기
  * 외부 레퍼런스 용어집 문서 가져오기/변환
  * 한→영 번역
  * 번역 전/후 AI 요약 생성 (현재도 프롬프트로 언제든 가능)
* 번역을 서브 에이전트 팀으로 진행하는 것은 현재로서는 바람직하지 않다는 판단입니다. (반대로 감수에는 서브 에이전트 운용 방식이 유리함)
* 학술적 아티클, 전문서적처럼 논리적으로 구조화된 문서가 아니라 소설, 수필 등 내용의 흐름이 중요한 문서에서는 각 chunk 앞에 직전 chunk의 끝 부분을 포함하여 맥락이 보존되도록 할 필요도 있을 수 있습니다. 현재는 이러한 오버랩 모드에 대한 구현이 되어 있지 않고 필요시 고려해야 한다는 지침만 기록해 AI가 대응을 시작할 수 있도록 하고 있습니다.
